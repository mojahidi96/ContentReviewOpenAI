# Prompt: integrate the Python content-review API into the Node.js service

Copy everything below the line into the Node.js repo's coding assistant.

---

Integrate our private Python AI service's content-review endpoint into this Node.js `ContentReviewService`. Inspect the existing code first and match its conventions (HTTP client, config, error handling, types, tests).

## Endpoint

`POST {AI_SERVICE_BASE_URL}/internal/v1/content-reviews`

Headers: `Authorization: Bearer ${INTERNAL_SERVICE_TOKEN}`, `Content-Type: application/json`, optional `X-Request-ID` (forward our correlation ID).

Request:

```json
{ "requestId": "review_123", "content": "Please recieve the document.", "language": "en" }
```

- `requestId`: 1-128 chars. `content`: 1-100,000 chars. `language`: optional, default `"en"`.
- No other fields are allowed (unknown fields return 422). The old `categories` field no longer exists.

Success (200):

```json
{
  "requestId": "review_123",
  "issues": [
    {
      "id": "issue-3f9a1c2b7d10",
      "issueType": "spelling",
      "severity": "low",
      "original": "recieve",
      "improved": "receive",
      "suggestion": "Correct the spelling mistake.",
      "location": { "prefix": "Please ", "suffix": " the document." }
    }
  ],
  "model": "gemini-...",
  "usage": { "inputTokens": null, "outputTokens": null }
}
```

- `issueType`: `spelling | grammar | typo | punctuation | clarity | slang | vulgarity | deprecated_term | inappropriate_language`
- `severity`: `low | medium | high`
- Issues are in document order. `id` is generated by the Python service.
- There are no character offsets. To place an issue, find `original` in the content using `prefix` and `suffix` (when `original` occurs more than once, pick the occurrence whose surrounding text matches). `prefix` or `suffix` may be empty at the start or end of the content.
- The service has already dropped issues whose `original` isn't in the content, so a missing match on your side means the content changed since the request.

Errors use `{ "error": { "code", "message", "requestId" } }`:

| Status | code | Handling |
|---|---|---|
| 401 | `UNAUTHORIZED` | Config bug; do not retry |
| 413 | `CONTENT_TOO_LARGE` | Reject or split content |
| 422 | `INVALID_REQUEST` | Bug in our payload; do not retry |
| 429 | `LLM_QUOTA_EXHAUSTED` | Back off; surface as "try later" |
| 502 | `INVALID_MODEL_OUTPUT` | Retry once |
| 503 | `LLM_PROVIDER_UNAVAILABLE`, `AI_CONCURRENCY_LIMIT` | Retry with backoff (max 2) |

## What to build

1. Config: `AI_SERVICE_BASE_URL`, `INTERNAL_SERVICE_TOKEN` (never log the token, content, or issue text).
2. A typed client method `reviewContent({ requestId, content, language? })` returning the response above, with a request timeout of about 60s (the call is synchronous and LLM-backed).
3. Map the error codes to our own error types per the table.
4. Wire it into the existing review flow, replacing any use of the old `findings` / `startOffset` / `endOffset` / `categories` shape.
5. Unit tests with a mocked HTTP layer covering: success, empty `issues`, each error status, and the retry behavior.

Do not change the Python service.
